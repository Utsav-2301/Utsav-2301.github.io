In 2015, Joseph Redmon, Santosh Divvala, Ross Girshick, and Ali Farhadi introduced a novel algorithm for object detection. 

They named it YOLO — You Only Look Once — for a specific reason. Earlier object detection models, like the R-CNN series, were also performing both classification and localization, but not in a single step: they relied on multiple stages (proposing candidate regions, classifying them, then refining the boxes) and multiple passes over the image. 

YOLO collapsed all of that into a single stage — one pass over the image to do both classification and localization at once.

![Regression problem framing](/images/yolo-v1/1.png)

## Output Tensor

YOLOv1 outputs a tensor of shape S×S×N, where S is 7 in the paper and N is 30. The authors trained on the [Pascal VOC](https://www.robots.ox.ac.uk/~vgg/projects/pascal/VOC/) dataset, which had 20 unique classes.

Each grid cell predicts 2 bounding boxes, and each bounding box has 5 values, giving us:

2 × 5 + 20 = 30

![7x7x30 output tensor](/images/yolo-v1/tensor_7x7x30.png)

Each bounding box is represented as [x, y, w, h, p], where x and y are the center coordinates of the box, w and h are its width and height, and p is the confidence score — not simply "objectness," but `Pr(Object) × IOU(pred, truth)`, which captures both whether an object is present and how well the predicted box actually aligns with it.

Each cell can only predict one object's class, which is a real limitation of this approach. If multiple objects' centers happen to fall inside the same grid cell, only one of them can be represented — the other is simply lost. This isn't decided by confidence or IOU; it's an inherent limitation of the grid-based design itself.

Within a cell, IOU does play a role, but for a different decision: choosing which of the cell's 2 predicted boxes is "responsible" for the assigned object. Once an object is assigned to a cell, its ground-truth box is compared against both predicted boxes, and whichever has the higher IOU becomes responsible for predicting that object during training.


## Small Object Limitation

YOLOv1 had one more significant issue: it struggled to localize small objects in an image. The reason comes down to how the network processes the image — as it passes through successive convolution and pooling layers, spatial features get progressively downsampled. By the time the network produces its final output, fine-grained details belonging to small objects can be heavily compressed or lost entirely, making them hard to detect and localize.

Consider a squirrel sitting on a tree branch. To a human eye, it's clearly visible and easy to identify. But after repeated convolution and pooling operations, the features representing that squirrel get compressed into a very small, coarse signal — making it much harder for the model to localize accurately.


So each grid cell effectively summarizes information from a 64 × 64 patch of the original image. A small object like a squirrel might occupy only a tiny fraction of that patch — yet the model has to represent it using the same single cell.

![Original squirrel photo](/images/yolo-v1/squirrel.jpg)

The authors themselves acknowledged this limitation in the paper. To see why, compare the input and output sizes: the input image is resized to 448 × 448, while the output is a 7 × 7 grid (each cell holding a 30-value tensor, as covered above). For spatial intuition:

448 / 7 = 64

![Squirrel photo with 7x7 grid overlay](/images/yolo-v1/squirrel-grid.png)

The grid overlay isn't a literal picture of the tensor — it's there to build intuition for how much of the original image's detail gets compressed into a single cell by the time the forward pass is done.

![Zoomed grid cell showing downsampled detail](/images/yolo-v1/final-grid.png)

## Multi-Object Limitation

As covered in the previous section, each grid cell predicts 2 candidate bounding boxes for a single object, not two independent object slots — IOU decides which of the two becomes "responsible" during training.

This raises a natural question: what happens if two different objects — say a cat and a dog — both have their centers inside the same grid cell? YOLOv1 cannot represent both. Each cell holds only one set of class probabilities and one object target, so one of the two is simply left undetected.

Importantly, which object gets represented isn't decided by confidence or IOU — it's an inherent limitation of the grid-based formulation itself. This is especially problematic when multiple small or closely packed objects share a cell, compounding the small-object issue discussed earlier.



## Normalization and Localization Loss

All predicted values are normalized into a range of 0 to 1 — but not all relative to the same thing. The center coordinates (x, y) are normalized as offsets relative to the bounds of their own grid cell, while the width and height (w, h) are normalized relative to the dimensions of the entire image. This matters because it keeps every predicted value on a comparable scale, regardless of where or how large the object is.

Once predicted, these values feed into the localization loss. For the center coordinates, the loss is a straightforward squared error: `(x - x̂)² + (y - ŷ)²`. For width and height, though, the authors used the squared error of the square root of each value instead of the raw value:

`(√w - √ŵ)² + (√h - ĥ)²`

The reasoning is simple: a small deviation matters more for a small object than for a large one, but plain squared error can't tell the difference. For example:

Suppose we have two boxes:

Large box:
- Actual width = 100
- Predicted width = 110
- Error = 10

Small box:
- Actual width = 10
- Predicted width = 20
- Error = 10

With squared error: 10² = 100 for both — so both get exactly the same loss. But intuitively, they're not equally bad:
- Large box: 100 → 110 is a 10% error
- Small box: 10 → 20 is a 100% error

Sum-squared error treats the same absolute error equally regardless of box size, even though a 10-pixel error is far more significant for a small box than a large one.

Taking the square root of w and h before computing the squared error fixes this. The square-root curve is steep for small values and flattens out for large ones, so the same absolute error produces a larger transformed error for small boxes and a smaller one for large boxes — making the loss more sensitive to errors on small objects, and less sensitive to the same absolute error on large ones.

![Square vs square root delta comparison](/images/yolo-v1/sqrt_vs_linear.png)


## Activation Function Choice

YOLOv1 uses Leaky ReLU for most of its convolutional layers. ReLU suppresses negative activations by setting them to zero, which provides a sparse, nonlinear feature representation.

However, when an activation is negative, ReLU also produces a zero gradient, which can cause a neuron to become permanently inactive and stop receiving useful gradient updates — the "dying ReLU" problem.

Leaky ReLU keeps the useful behavior of ReLU while allowing a small negative value, and more importantly, a small non-zero gradient, to pass through when the input is negative.

![ReLU vs Leaky ReLU](/images/yolo-v1/relu_vs_leaky_relu.png)

This lets neurons keep learning even when their activations are negative — useful when training a deep network like YOLOv1 end-to-end. It's a design choice rather than a universal rule; ReLU-family activations remain a common default, though later architectures (including later YOLO versions) have used alternatives like Swish or Mish.

## Loss Function Walkthrough

![Loss Function](/images/yolo-v1/loss_function.png)

YOLOv1's total loss is a sum of coordinate loss, confidence loss, and classification loss, computed per grid cell and combined into a single scalar used for backpropagation.

The grid has S² = 49 cells, and each cell predicts B = 2 bounding boxes. For each box, we compute:

- **Coordinate loss** — but only for the *responsible* predictor (the box with higher IOU against the ground truth, as covered earlier):
  `λ_coord · [(x - x̂)² + (y - ŷ)²]`
  `+ λ_coord · [(√w - √ŵ)² + (√h - ĥ)²]`

- **Confidence loss** — computed for *every* predicted box, but split into two cases:
  - If the box is the responsible predictor for an object: `(C - Ĉ)²`
  - Otherwise (no object in the cell, *or* this is the non-responsible box in a cell that does have an object): `λ_noobj · (C - Ĉ)²`

This second case is easy to misread — `λ_noobj` doesn't just apply to empty cells. It also downweights the confidence loss for the "losing" box inside a cell that *does* contain an object, since only one of the two boxes gets to be responsible.

`λ_coord = 5` and `λ_noobj = 0.5` exist for a scale problem: the 4 coordinate values are a small fraction of the 30 values per cell, so they need to be upweighted to matter; meanwhile the vast majority of the 49 cells contain no object at all, so their confidence-loss gradients would otherwise dominate training and drown out the (relatively rare) genuine detections.

- **Classification loss** — unlike the two terms above, this is computed once *per cell*, not per box, since both boxes in a cell share the same set of class probabilities:
  `Σ (p_i(c) - p̂_i(c))²` for each class `c`, only for cells that actually contain an object.

Together, these three terms — coordinate, confidence, classification — sum into the total loss. Gradient descent then repeatedly updates the network's weights to reduce this loss, continuing until further updates produce negligible improvement.
